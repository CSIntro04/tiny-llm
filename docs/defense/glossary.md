# 概念速查

每条 2–3 句，答辩前通读一遍。

## 数据与词元化

- **Next-token prediction（下一个词元预测）**：给定前面的 token，预测下一个 token 的概率分布。训练目标就是让真实的下一个 token 概率尽量大；这个简单任务迫使模型学会语法、常识和上下文关系。
- **Token / 词元化（Tokenization）**：把文本切成模型处理的基本单位并映射为整数 id。可以按字符、按词或按子词（BPE）切分。
- **BPE（Byte Pair Encoding）**：从单个字节开始，反复统计语料中最常出现的相邻对并合并成新符号，直到词表达到目标大小。常见词会变成一个 token，罕见词被拆成几段，没有未登录词问题。
- **Epoch（轮次）**：模型完整看过一遍训练集。数据不够时要多轮训练，同一数据看太多遍容易过拟合。

## 模型结构

- **Embedding（嵌入）**：一张 `V × C` 的查找表，把 token id 变成 C 维向量。向量是学出来的，语义相近的词向量会靠近。
- **位置编码（Positional encoding）**：注意力本身不区分顺序，需要把"第几个位置"的信息加进输入。本项目用可学习的位置嵌入 `wpe`；RoPE 是另一种把位置信息"旋转"进 q、k 的方法，长度外推更好。
- **自注意力（Self-attention）**：每个位置生成 query、key、value，用 q 和所有 k 的点积决定"关注谁"，再按权重加权求和 v。它让每个 token 能直接从上下文任意位置获取信息。
- **多头注意力（Multi-head）**：把 C 维拆成 nh 个 hs 维的子空间，各自独立做注意力再拼接。不同的头可以学习不同类型的关系。
- **因果掩码（Causal mask）**：把注意力矩阵上三角设为 -∞，使位置 i 只能看到 ≤ i 的位置。保证训练时不"偷看答案"，与逐字生成时的条件一致。
- **残差连接（Residual）**：`x = x + f(x)`，子层只需学习"增量"。梯度可以沿恒等路径直接传回浅层，深层网络才训练得动。
- **LayerNorm**：对每个 token 的 C 维向量做归一化（减均值除标准差）再缩放平移，稳定数值范围。Pre-LN 把它放在子层之前，训练更稳定。
- **MLP（前馈层）**：每个位置独立的两层全连接 `C → 4C → C`，中间用 GELU 激活。注意力负责位置间交流，MLP 负责每个位置上的非线性"思考"。
- **权重共享（Weight tying）**：输出层 `lm_head` 与输入嵌入 `wte` 用同一个矩阵。省掉 `V × C` 个参数，也让"输入的词义"与"输出的词义"保持一致。
- **Decoder-only**：只用带因果掩码的 Transformer 解码器堆叠（GPT 系列），没有编码器和交叉注意力，适合自回归生成。

## 损失与评估

- **交叉熵（Cross entropy）**：对正确 token 取 `-log p`，再对所有位置求平均。最小化它就是最大化训练数据的似然；随机初始化时模型对 V 个 token 均匀猜测，loss ≈ ln V。
- **困惑度（Perplexity）**：`exp(loss)`，可以理解为"模型平均在多少个候选里犹豫"。困惑度 10 表示和在 10 个词里均匀猜一样不确定。
- **过拟合（Overfitting）**：模型记住了训练集细节，train loss 继续下降而 val loss 停滞或上升。监控 train–val 差距可以发现它。
- **Bits-per-byte（bpb）**：把 loss 换算成"每个字节需要多少比特"，可以在不同分词器之间公平比较。

## 训练

- **AdamW**：Adam 为每个参数维护梯度的一阶、二阶动量，自适应调整步长；AdamW 把权重衰减与梯度更新解耦，正则化效果更正确。
- **Warmup + cosine**：开始若干步学习率从 0 线性升高，避免初期大步长发散；之后按余弦曲线逐渐降到最小值，后期精细收敛。
- **梯度裁剪（Gradient clipping）**：梯度总范数超过阈值（如 1.0）时整体等比例缩小。防止偶发的梯度爆炸破坏训练。
- **梯度累积（Gradient accumulation）**：显存放不下大 batch 时，连续做几次小 batch 的前向反向、把梯度加起来再更新一次。效果近似一个大 batch，代价是更慢。
- **bf16 混合精度**：矩阵乘法用 16 位 bfloat16 计算，参数保持 fp32。bf16 的指数位与 fp32 相同、范围一样大，不会下溢，所以不需要 fp16 那样的 GradScaler。
- **梯度检查点（Gradient checkpointing）**：前向时不保存中间激活，反向时重新计算。用约 30% 的额外计算换取大幅减少的显存。
- **FlashAttention / SDPA**：`F.scaled_dot_product_attention` 会自动选择高效内核（如 FlashAttention），分块计算注意力、不显式存 T×T 矩阵，更快更省显存，结果与手写版本数学等价。
- **torch.compile**：把 PyTorch 模型编译成融合后的 GPU 内核，减少内存读写，通常提速 1.3–2 倍；首次编译需要一两分钟。
- **Scaling law / Chinchilla**：经验规律——loss 随参数量、数据量、计算量呈幂律下降。Chinchilla 研究认为计算最优时每个参数约配 20 个训练 token；数据少于这个量时大模型收益会打折扣。

## 生成

- **自回归生成**：每次预测一个 token，接到输入末尾，再预测下一个，循环往复。
- **Temperature**：采样前把 logits 除以 T。T<1 让分布更尖（保守、易重复），T>1 让分布更平（多样、易出错），T→0 等价于 greedy。
- **Top-k**：只在概率最高的 k 个 token 里采样。截掉低概率的长尾，避免偶尔抽到离谱的词。
- **Top-p（nucleus）**：只保留累计概率达到 p 的最少 token 集合。模型很确定时候选很少，不确定时候选变多，比固定 k 更自适应。
- **Greedy 解码**：每步都选概率最大的 token。结果确定，但容易陷入重复循环。
- **KV cache**：生成时缓存每层已算过的 key 和 value，新 token 只计算自己的部分。历史 token 的 k/v 不会变，所以可以复用；q 只对当前 token 有意义，不缓存。它不减少前向调用次数，但把每次 decode 的计算量从整个前缀降到 1 个新 token，长文本生成提升明显。
- **Prefill / Decode**：prefill 是首轮把完整 prompt 送进模型、算出一层层的 K/V 并预测第一个新 token；decode 是之后每次只送 1 个新 token，把它的 K/V 追加到 cache 再预测下一个。
- **滑动窗口与位置编码**：本项目的位置表 `wpe` 只有 `block_size` 行。生成超过上下文后只看最后 `block_size` 个 token，位置从 0 重新编号；因此 cache 到上限时要重建，不能简单丢掉最旧的 K/V。
