# 答辩问题清单与参考回答

汇总 01–08 各阶段文档末尾的"答辩可能被问的问题"。每题 2–4 句参考回答，尽量给出代码位置和本项目的实测数字。**每位组员都要能回答全部问题**，不只是自己负责的部分。概念速查见 [glossary.md](glossary.md)。

## 一、整体

**什么是 next-token prediction？为什么它能学到语言？**
给定前面的 token，预测下一个 token 的概率分布；训练目标是让真实的下一个 token 概率尽量大。要把这件事做好，模型必须学会语法（下一个词的词性）、常识（"plants convert ... into"后面接什么）和上下文关系（前文出现的名字）。这个目标不需要人工标注，任何文本都能当训练数据。

**Decoder-only 是什么？和原始 Transformer 的 Encoder-Decoder 有什么区别？**
原始 Transformer 是翻译模型：编码器双向读完原文，解码器一边看编码器输出一边逐词生成译文。Decoder-only 去掉了编码器和交叉注意力，只保留带因果掩码的自注意力层，输入和输出是同一个序列。GPT 系列都是这种结构，适合"续写"这种任务。

**整个流程是什么？**
文本 → 清洗 → BPE 编码成 token id → 存成 uint16 的 .bin（`src/prepare.py`）→ 随机截取长度 513 的片段，x 是前 512 个、y 是后 512 个（`src/utils.py:15`）→ 模型输出每个位置对下一个 token 的打分 → cross entropy 损失 → 反向传播 + AdamW（`src/train.py`）→ 生成时每步取最后一个位置的分布抽样（`src/sample.py:106`）。

## 二、数据与词元化

**两个数据集分别是什么？为什么混合？比例怎么定的？**
SmolLM-Corpus 1B 子集是教育类网页（FineWeb-Edu 87%）和合成教科书（Cosmopedia 13%），词汇和知识面广；TinyStories 是只用儿童词汇的短故事，结构简单，小模型也能写出连贯的故事。混合后可以分来源看 val loss，观察规模收益在难/易文本上的差别。比例按各来源训练 token 数自然混合（70.3% : 29.7%），训满一轮时每个 token 恰好看一遍。

**什么是 token？BPE 怎么训练？**
token 是模型处理的基本单位，每个 token 对应一个整数 id。BPE 从 256 个字节开始，反复统计语料里最常出现的相邻对并合并成新符号，直到词表达到 8192。可以现场跑 `python src/tokenizer.py` 演示手写 BPE：前几次合并是 `h+e → he`、`' '+t → ' t'`、`' t'+he → ' the'`（`src/tokenizer.py:183`）。正式训练用的是 HF `tokenizers` 库的 ByteLevel BPE，算法相同，速度快得多。

**词表为什么选 8192？embedding 占多少参数？**
embedding 是 V×C 的表，词表越大，参数越多：s10m 的 embedding 是 8192×384 = 315 万；如果用 GPT-2 的 50257 词表就是 1930 万，比模型其余部分（1065 万）还大。但词表太小会把一个词切成很多碎片，512 的上下文能装的内容变少。8192 下平均每个 token 约 3.9 个字符，是两者的折中。

**SmolLM 的验证集怎么切的？为什么按文档切？**
没有官方验证集，我们按文档哈希切出 0.5%（`src/prepare.py:171`，`is_val`）。按文档而不是按 token 切，是为了避免同一篇文章的前半段在训练集、后半段在验证集，让 val loss 偏乐观。用哈希而不是随机数，结果只取决于文档内容，可复现，重复文档也一定落在同一边。

**x 和 y 是什么关系？**
y 就是 x 向右移一位：`x = data[i : i+512]`，`y = data[i+1 : i+513]`。位置 t 的预测目标是位置 t+1 的真实 token，所以一个长度 512 的序列同时提供了 512 道"预测下一个词"的题。

**数据许可是什么？要注意什么？**
SmolLM 是 ODC-By 1.0，使用时需要署名；TinyStories 是 CDLA-Sharing-1.0，再分发数据时要用同样的许可。我们的仓库不包含原始数据，只包含分词器和统计信息，README 里写了署名。

## 三、模型

**注意力的计算过程和张量形状？**（`src/model.py:66-95`）
输入 `(B,T,C)` 经过 `c_attn` 变成 `(B,T,3C)`，拆成 q、k、v 各 `(B,T,C)`；再 view 成 `(B,T,nh,hs)`、transpose 成 `(B,nh,T,hs)`，让每个头独立计算。`q @ kᵀ / √hs` 得到 `(B,nh,T,T)` 的打分矩阵，第 i 行是位置 i 对各位置的关注程度；加因果掩码、softmax 后乘 v 得到 `(B,nh,T,hs)`，最后 transpose + view 合并回 `(B,T,C)`，经过 `c_proj` 混合各头的信息。

**因果掩码的作用？去掉会怎样？**
掩码让位置 i 只能看到 j ≤ i 的位置。训练时一次喂入整句并行预测每个位置的下一个词，如果位置 i 能看到 i+1，就等于直接看到了答案：训练 loss 会降得极低，但生成时没有未来信息，模型完全不会写。测试 `tests/test_model.py` 里检查了"修改位置 t 之后的 token，位置 0..t 的 logits 不变"。

**为什么除以 √d？**
q、k 每一维近似独立、方差为 1 时，点积的方差是 hs（64）。不缩放的话打分的数值很大，softmax 会接近 one-hot，梯度几乎为零。除以 √hs 把方差拉回 1。

**多头的意义？**
把 768 维拆成 12 个 64 维的子空间，每个头独立算注意力，可以同时关注不同的关系，比如一个头看前一个词、一个头看句子主语。参数量和单头一样，只是分组计算。

**残差连接和 LayerNorm 的作用？Pre-LN 和 Post-LN 的区别？**（`src/model.py:122-127`）
残差 `x = x + f(x)` 让子层只学"增量"，梯度可以沿恒等路径直接传回浅层，深层网络才训练得动。LayerNorm 把每个 token 的向量归一化，稳定数值范围。原论文是 Post-LN（先加残差再归一化），我们用 Pre-LN（归一化放在子层之前），残差路径上没有任何变换，深层训练更稳定，不太依赖 warmup。

**权重共享省了多少参数？为什么合理？**（`src/model.py:142`）
输出层 `lm_head` 和输入的 `wte` 用同一个 V×C 矩阵，s100m 省 629 万参数，s10m 省 315 万（占总参数 22%）。合理性在于：输入时"id → 向量"和输出时"向量 → 和每个词有多像"是同一种语义对应关系，共享后两边互相提供训练信号，实践中效果通常更好。

**参数量怎么算？每层为什么约 12C²？**
注意力有 4 个 C×C 矩阵（q、k、v、输出投影）= 4C²，MLP 有 C×4C 和 4C×C 两个矩阵 = 8C²，合计 12C²；再加上 bias 和两个 LayerNorm 共 13C。s100m：12×768² + 13×768 = 7,087,872 每层，×14 层再加 embedding 6,291,456 和位置编码 393,216，总共 105.92M。`python src/model.py` 打印按组件拆分的统计，见 [model.md](model.md)。

**为什么位置编码是必须的？**
注意力只看 q、k 的内容，对顺序不敏感：打乱输入顺序，输出也只是跟着打乱。所以要把位置信息加进输入。我们用可学习的绝对位置编码 `wpe`（512×C），因此上下文最长 512。

## 四、损失

**为什么用 cross entropy？**（`src/model.py:184`）
每个位置都是一个 8192 类的分类问题。cross entropy 就是正确 token 的 −log p 的平均，最小化它等价于最大化训练数据的似然。它对"自信地猜错"惩罚很重，梯度形式也很简单（softmax 输出减 one-hot）。

**初始 loss 为什么 ≈ ln(V)？**
随机初始化时 logits 都接近 0，softmax 接近均匀分布，每个 token 的概率约 1/8192，loss = −ln(1/8192) = ln 8192 ≈ 9.01。我们实测 s10m 初始 val loss 9.07，s100m 9.18，符合预期；明显偏高的话说明初始化有问题。

**困惑度是什么？**
困惑度 = exp(loss)，可以理解为"模型平均在多少个候选词里犹豫"。s100m 的 val loss 2.409，困惑度 11.1；s10m 是 22.2。

## 五、训练

**为什么用 AdamW 而不是 SGD？和 Adam 有什么区别？**
Adam 给每个参数自适应地调整步长（用梯度一阶、二阶矩的估计），对 Transformer 这种各层梯度量级差异很大的模型比 SGD 好调得多。AdamW 把 weight decay 和梯度更新解耦，直接对参数乘一个衰减系数，而不是加到梯度里经过 Adam 的缩放。我们只对二维权重做 decay，bias 和 LayerNorm 不做（`src/model.py:198`）。

**warmup 解决什么问题？为什么后期要降学习率？**（`src/utils.py:110`）
刚开始参数是随机的、梯度方向不可靠，Adam 的二阶矩估计也还不准，一上来就用大步长容易发散，所以前 200 步从 0 线性升到峰值。之后按余弦曲线降到峰值的 1/10：后期用小步长在低谷附近精细收敛。我们的实验也看到，学习率衰减完的 checkpoint 比同 token 数但学习率还高的 checkpoint loss 低。

**梯度裁剪的作用？**（`src/train.py:236`）
如果所有参数梯度的总范数超过 1.0，就整体等比缩小到 1.0。偶尔遇到特别难的 batch 会产生很大的梯度，裁剪防止一步把参数"打飞"。方向不变，只限制步长。

**梯度累积是什么？和直接用大 batch 等价吗？**（`src/train.py:225-232`）
显存放不下 256 条序列时，把它拆成几个 micro-batch 依次前向、反向，梯度累加起来再更新一次参数。每个 micro-batch 的 loss 先除以累积次数，累加结果就等于大 batch 的平均梯度。数学上等价（只差浮点误差），差别只在 BatchNorm 这种依赖 batch 统计量的层，我们的模型没有。本地 8GB 显卡训练 s100m 就是 16 × 16。

**bf16 和 fp16 有什么区别？为什么 bf16 不需要 GradScaler？**
两者都是 16 位。fp16 指数位只有 5 位，能表示的最小数大约 6e-8，小梯度会下溢成 0，所以要先把 loss 放大（GradScaler）。bf16 有 8 位指数，和 fp32 的范围相同，只是精度低一些，不会下溢，所以不需要缩放。我们用 autocast：矩阵乘法用 bf16，参数和优化器状态仍是 fp32。

**训练 loss 和验证 loss 的差距说明了什么？**
差距大（train 远低于 val）说明过拟合，在背训练集。我们三个模型的 train − val 一直在 ±0.08 内波动（`docs/figures/train_val_gap.png`），没有过拟合：s100m 只训练了 0.92 轮，大部分数据只看过一次。

**一个 epoch 是多少步？你们的模型看了几遍数据？**
训练集 16.3 亿 token，每步 131072 token，一轮约 12,437 步。s10m 训练 2,290 步（约 18%），s50m 7,630 步（61%），s100m 11,450 步（0.92 轮），都没有超过一轮。

**为什么 50 系显卡需要 CUDA 12.8？**
RTX 50 系是 Blackwell 架构（sm_120），只有 CUDA 12.8 以上的编译器能为它生成 kernel。老版本 PyTorch 没有这些 kernel，会报 `no kernel image is available`。

## 六、生成

**模型输出的是什么？怎么从 logits 变成一个具体的词？**（`src/sample.py:71`）
模型对最后一个位置输出 8192 个打分（logits）。先除以 temperature，再按 top-k / top-p 把候选范围之外的打分设成 −∞，softmax 变成概率分布，最后按概率随机抽一个 token。把它接到输入末尾，重复这个过程。

**temperature 的数学含义？T→0 和 T→∞ 分别会怎样？**
概率 = softmax(z / T)。T < 1 放大打分差距，分布更尖；T > 1 缩小差距，分布更平。T→0 时变成 one-hot，就是 greedy（总选概率最大的）；T→∞ 时变成均匀分布，完全随机。实验 B：T=1.5 时出现了"Cariboo chrysog"这类不存在的词。

**top-k 和 top-p 的区别？各自的优缺点？**
top-k 只在概率最高的 k 个词里抽，简单，但 k 是固定的：模型很确定时 k=50 也嫌多，很不确定时又嫌少。top-p 保留累计概率刚好达到 p 的最小集合，候选数量随分布自动变化。实验 B 中 T=1.0 下 top-k=50 和 top-p=0.9 效果接近；T=1.5 时 top-k=50 能把乱码拉回正常拼写。

**为什么 greedy 解码容易重复？**
每步都选最可能的词，一旦生成了一个循环，循环里的每一步本身都是"最可能"的，模型就跳不出来。实验 B 里 greedy 的说明文整句复读"What is the difference between photosynthesis and photosynthesis?"，distinct-2 只有 0.53。

**上下文超过 512 个 token 怎么办？**
位置编码只有 512 个，生成时只保留最后 512 个 token 作为输入（`src/sample.py:119`），更早的内容模型看不到。

**生成一段文本时模型前向了多少次？**
每生成一个 token 前向一次，生成 200 个 token 就是 200 次。我们没有做 KV cache，每次都把整个上下文重新算一遍；KV cache 会把之前位置的 k、v 存下来，每步只算新 token，速度能快很多。

## 七、实验

**你们的对比公平吗？控制了哪些变量？**
三个模型用同一份数据、同一个分词器、同一个随机种子、同样的有效 batch（131072 token/步）、同样的 warmup 和 cosine 调度、同样的优化器设置。只有结构、学习率和训练 token 数不同，学习率是按模型大小选的常用值。

**三个模型训练的 token 数不同，怎么保证比较公平？**
除了比最终 loss，还用训练中途保存的 `ckpt_tok100M/300M/1000M.pt` 在同一批验证数据上重新评估（`src/evaluate.py`）。在 3 亿 token 处，s10m 3.082，s50m 2.843，s100m 2.810，大模型仍然更低，而且这时大模型的学习率还没衰减，比较对它们是不利的。

**为什么大模型学习率要小？**
参数越多、层越深，同样的学习率下每一步对输出的影响越大，训练更容易不稳定。经验上峰值学习率随宽度增大而减小，我们用 1e-3、6e-4、4e-4。

**什么是 scaling law？你们的结果符合吗？**
loss 随参数量和数据量按幂律下降：每多花 10 倍计算量，loss 下降的幅度越来越小，最终趋近数据本身的熵。我们三个点的计算量约 2.5e16、3.3e17、9.5e17 FLOPs，每 10 倍计算量，前一段 loss 降 0.50、后一段降 0.29，往右越来越平，和幂律的形状一致（`docs/figures/scaling.png`）。只有三个点，不足以拟合出可靠的指数。

**0.1B 模型的数据够吗？怎么判断欠拟合还是过拟合？**
看 train 和 val 的差距：过拟合时 train 明显低于 val；我们的差距一直在 ±0.08 内，没有过拟合。s100m 用了 15 亿 token，约 14 token/参数，比 Chinchilla 的约 20 略少，val loss 到最后还在下降，所以更可能是欠拟合，多给数据还会更好。

**为什么小模型在 TinyStories 上还行，在 SmolLM 上差很多？**
TinyStories 词汇少、句式固定，s10m 的 loss 就已经到 1.85；SmolLM 是真实网页和教科书，词汇和知识面广得多，需要记住的东西多，模型容量就成了瓶颈。从 s10m 到 s100m，SmolLM 降了 0.76，TinyStories 只降了 0.52。

**temperature 设多少最好？为什么？**
我们推荐 T=0.7–0.8 加 top-k=50，界面默认 T=0.8。更低会陷入循环，更高会出现乱码；这组设置既不容易复读，也很少拼错词。但"最好"取决于任务，distinct-2 高不代表质量好，要结合人工阅读看。

**盲评是怎么做的？结果可信吗？**
30 条样本打乱顺序、隐藏模型名，三位组员独立按语法、连贯、事实、重复打 1–5 分。R3 的"重复"一项和自动指标的相关系数是 −0.75（另外两人是正的），判断为理解反了规则，按 6−x 换算，文档里如实记录了。每格只有 5 条样本，相差 0.2 以内看作持平。

**字符级和 BPE 为什么不能直接比 loss？**
字符级每个 token 是 1 个字符，BPE 每个 token 约 3.9 个字符，"每个 token 的 loss"衡量的东西不一样。我们换算成 bits-per-byte（总 NLL / ln2 / 字节数），在同一段原文上比较：SmolLM 上 BPE 1.367、字符级 1.602，BPE 更好。

**三个模型的输出差异和 loss 的差距一致吗？**
基本一致。s10m 到 s50m 的 loss 差距大（0.555），盲评里故事的语法、连贯分也提升明显；s50m 到 s100m 的 loss 只差 0.134，故事分几乎一样，只有说明文还在进步。

## 八、展望与个人

**如果给你们更多时间/算力，下一步做什么？**
① 更多数据、训练更久，s100m 现在还在欠拟合；② 换 RoPE 位置编码，把位置信息"旋转"进 q、k，可以处理比训练时更长的上下文；③ 加 KV cache，生成速度能快很多；④ 加大上下文长度；⑤ 用问答数据做指令微调，让模型能回答问题而不只是续写。

**这个项目里你个人负责什么？遇到的最大问题是什么？**（各自准备，提纲）
- A（数据 + 采样）：TinyStories 约 6% 的故事引号乱码（`â€™`），修复前一个分片要丢 3.2 万篇，修复后全量只丢 406 篇；top-p 实现时第一个让累计概率超过 p 的 token 要保留。
- B（模型 + 训练）：权重共享与初始化的顺序；`load_model` 直接读到 GPU 时 AdamW 状态白占显存；本地 8GB 跑不动正式训练，改到云端 5090。
- C（实验 + 界面 + 报告）：相同 token 数比较要单独评估中途 checkpoint；盲评 R3 反向打分的发现和处理；字符级 vs BPE 必须换算到 bpb。
